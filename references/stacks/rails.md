# Ruby on Rails

## detection signals
`Gemfile` with `gem "rails"`, `bin/rails`, `config/application.rb` defining a `Rails::Application`, `config/routes.rb`, `app/controllers/`, `config/environments/{development,test,production}.rb`. Version from `Gemfile.lock` (the `rails (x.y.z)` line) or `bin/rails --version` — Rails 7 and Rails 8 differ enough on auth, asset pipeline, and job adapter that you should read the version before assuming any default below. API-only mode is `config.api_only = true` in `config/application.rb`; it removes the cookie, session, flash, and CSRF middleware, which changes several checks. A `Procfile.dev` plus `bin/dev` means the app has a JS/CSS build alongside the server. An `app/views/` tree means server-rendered HTML; its absence with `api_only` means the frontend is a separate project with its own stack file.

## dev server
`bin/rails server` (`bin/rails s`), default port 3000, override with `-p`/`--port` or `PORT=`. If `bin/dev` and `Procfile.dev` exist use that instead — it runs the server plus the asset watchers (esbuild/Tailwind), and without it the CSS and JS are stale. Ready when `GET /` returns any status; `GET /up` is the built-in health route in Rails 7.1 and later. `RAILS_ENV` defaults to `development`, where `consider_all_requests_local` is true and every error renders a full stack trace with source — so never measure error bodies, headers, caching, or asset sizes against the dev server. See "build" for the production-mode run that every local-tier check wants.

## build
Rails does not bundle the server. Three things happen before production runs:
1. `bundle install` (use `bundle install --deployment` or `BUNDLE_FROZEN=true` for the clean-clone reproduction HYG-015 wants; the lockfile is `Gemfile.lock`).
2. Asset compilation: `RAILS_ENV=production bin/rails assets:precompile` → `public/assets/` (plus `app/assets/builds/` for jsbundling). Propshaft is the Rails 8 default pipeline, Sprockets the older one (`config/initializers/assets.rb`, `app/assets/config/manifest.js`); check `Gemfile` for `propshaft` vs `sprockets-rails`. If `jsbundling-rails`/`cssbundling-rails` are present, `assets:precompile` shells out to `yarn build`/`npm run build` first, so the real bundler config is `esbuild.config.js`, `rollup.config.js`, or the `scripts.build` line in `package.json` — that is where a `--sourcemap` flag lives (SEC-007) and where any client-visible env inlining happens (SEC-003). `importmap-rails` apps have no bundler at all: JS is served as-is from `app/javascript` and `vendor/javascript`, so there is nothing to grep for a leaked secret except the served files themselves.
3. Production boot: `RAILS_ENV=production SECRET_KEY_BASE=<value> RAILS_SERVE_STATIC_FILES=1 PORT=3100 bin/rails server`. `SECRET_KEY_BASE` is mandatory in production and is normally read from credentials (see "env vars") — if credentials cannot be decrypted the app will not boot. `RAILS_SERVE_STATIC_FILES` is needed because production defaults to letting a reverse proxy serve `public/`; without it every asset 404s and every performance measurement is wrong. `RAILS_LOG_TO_STDOUT=1` puts the log where you can read it.

`Dockerfile` is generated by default in Rails 7.1+; if one exists it is the authoritative build and `docker build` is the clean-clone reproduction.

Two things other domains ask of this section. Compression (PERF-003) is `Rack::Deflater` inserted in `config/application.rb`, or more usually the proxy or CDN in front — Rails enables none by default. Deployment shape (PERF-016): Rails normally runs as a long-lived Puma process, so there is no cold start to measure and that check is `n/a — long-lived process`; say so rather than leaving it blank. If the app is deployed to a scale-to-zero container platform, the platform's own stack file owns the number.

## env vars
Two systems, and most apps use both.

**Environment**: `ENV['X']`, `ENV.fetch('X')`, `ENV.fetch('X', 'default')`, `ENV['X'] || 'default'`. Grep all four forms for REL-008 — `ENV.fetch('X')` raises on a missing value (loud, survivable), `ENV['X']` returns `nil` silently, and a second argument or an `||` is the silent-fallback failure REL-008 exists to catch. `dotenv-rails` (check the `Gemfile`) loads `.env`, `.env.<RAILS_ENV>`, `.env.local`, `.env.<RAILS_ENV>.local` in development and test only, not in production unless the app explicitly requires it there. REL-008's second set — the variables that are *declared* — comes from `.env.example` / `.env.sample` if the project keeps one, plus the deploy config (`Dockerfile` `ENV` lines, `fly.toml`, `render.yaml`, `kamal/deploy.yml`'s `env` block, the CI workflow); Rails projects frequently have no example file at all, which is itself the finding.

**Encrypted credentials**: `config/credentials.yml.enc` decrypted with `config/master.key` or `RAILS_MASTER_KEY`; per-environment variants are `config/credentials/production.yml.enc` + `config/credentials/production.key`. Read them with `bin/rails credentials:show` and `bin/rails credentials:show --environment production`. Code reads them as `Rails.application.credentials.stripe[:secret_key]` or `Rails.application.credentials.dig(:aws, :access_key_id)`. The key files must be gitignored — the generated `.gitignore` covers them, but confirm with `git ls-files | grep -E 'master\.key|credentials/.*\.key'`; a committed key makes every credential in the repo public (SEC-001, SEC-002). Very old apps use `config/secrets.yml`; `figaro` uses `config/application.yml`. `SECRET_KEY_BASE` may come from either system.

**Public prefix**: Rails has none. Nothing is inlined into client JavaScript by the framework. For SEC-003, the client-reachable surfaces are: values written into a layout (`<meta name="stripe-key" content="<%= ... %>">`, a `javascript_tag` or `data-` attribute in `app/views/layouts/`), anything defined at bundle time in the JS bundler config (`--define:process.env.X=` in an esbuild script), and `window.` assignments in `app/javascript/`. Grep those three, then grep `public/assets/` after a precompile for the actual key values from credentials and `.env`.

**Payment test-mode detection**: read `ENV['STRIPE_SECRET_KEY']` from the running process (`printenv | grep -i stripe`) and, if the app uses credentials, `bin/rails runner 'puts Rails.application.credentials.dig(:stripe, :secret_key).to_s[0, 8]'` — the `sk_test_` / `pk_test_` prefix is the tell, and printing eight characters is enough.

## routes and handlers
`config/routes.rb` is the whole route table, but read it with the tool rather than by eye: `bin/rails routes` prints every path, verb, controller#action, and named helper; `bin/rails routes --expanded` is one block per route; `bin/rails routes -g <pattern>` filters; `bin/rails routes -c <controller>` scopes to one controller. Run it once and work from the output — `resources :posts` expands to seven routes and a `namespace`/`scope` block changes every path under it, so a visual read of `routes.rb` will miss endpoints.

Handlers are `app/controllers/**/*_controller.rb`, one public method per action. Shared behaviour lives in `ApplicationController` and `app/controllers/concerns/`. Views `app/views/<controller>/<action>.html.erb` (or `.haml`/`.slim`), layouts `app/views/layouts/application.html.erb` — that layout is where analytics tags, consent gating, and the `<html lang>` attribute live. Mailers `app/mailers/` with templates in `app/views/<mailer>_mailer/`; previews in `test/mailers/previews/` or `spec/mailers/previews/` render at `/rails/mailers` in development, which is what HYG-016 wants. ActionCable channels `app/channels/` (SEC-055). Jobs `app/jobs/`. Anything `mount`ed in `routes.rb` — `Sidekiq::Web`, `GoodJob::Engine`, `letter_opener_web`, `PgHero`, `Flipper::UI` — is a third-party admin surface reachable over HTTP and is SEC-013's business.

Not-found and error routes: unmatched paths raise `ActionController::RoutingError`, which Rails renders as `public/404.html` unless `config.exceptions_app = self.routes` is set and an `ErrorsController` handles `/404`, `/500`, `/422`.

## auth
Find the mechanism first, then find where it is applied and where it is skipped.

**Devise** (`gem "devise"`, `config/initializers/devise.rb`, `devise_for :users` in routes): the guard is `before_action :authenticate_user!`, normally declared once in `ApplicationController`. The gap to hunt is `skip_before_action :authenticate_user!` — grep for it and read the `only:`/`except:` arguments; a bare `skip_before_action :authenticate_user!` at the top of a controller unprotects every action in it, and that is the single most common SEC-010 finding on this stack. `current_user`, `user_signed_in?`, and `authenticate_user!` are the helpers. Devise's own `config.paranoid` setting in the initializer governs whether reset and confirmation responses reveal whether an address exists (SEC-018).

**Rails 8's built-in generator** (`bin/rails generate authentication`) produces `app/models/session.rb`, `app/models/current.rb`, and an `Authentication` concern whose guard is `require_authentication` with `allow_unauthenticated_access only: [...]` as the opt-out. This ships in Rails 8; Rails 7 has no such generator, so check the version before looking for these files.

**Other**: `has_secure_password` on the model with hand-written session controllers, Sorcery, Clearance, Rodauth, `devise-jwt` or `doorkeeper` for token auth.

**Object-level and role checks** (SEC-011, SEC-012): Pundit (`app/policies/`, `authorize @post`, `policy_scope(Post)`, and `after_action :verify_authorized` which is what makes a missing `authorize` call fail loudly), CanCanCan (`app/models/ability.rb`, `load_and_authorize_resource`), or hand-written `current_user.admin?` checks. Admin engines: ActiveAdmin (`app/admin/`, gated by `config.authentication_method` and `config.authorization_adapter` in `config/initializers/active_admin.rb`), Administrate, Avo — read that config, because the default in a fresh install is often no gate at all.

**Session**: `config/initializers/session_store.rb` sets the cookie name (`Rails.application.config.session_store :cookie_store, key: '_myapp_session'`); the default is `_<app_name>_session`. Cookies are `HttpOnly` by default; `Secure` follows `config.force_ssl = true`; `SameSite` comes from `config.action_dispatch.cookies_same_site_protection` (`:lax` under modern `config.load_defaults`) — check the value the app's `load_defaults` line actually implies rather than assuming (SEC-025). Devise's remember-me cookie is `remember_user_token`. Session expiry is `expire_after:` on the session store, or Devise's `config.timeout_in`.

## webhook handlers
Controllers under `app/controllers/webhooks/` or named `*_webhooks_controller.rb`, routed with an explicit `post` in `routes.rb`. Each needs `skip_before_action :verify_authenticity_token` (the provider has no CSRF token) and `skip_before_action :authenticate_user!` (the provider has no session) — both skips are legitimate here and only here, which is what SEC-030 asks you to justify. The raw body is `request.raw_post`; `request.body.read` works but rewinding matters if anything read it first, and `params` is a re-parsed copy that will not verify. `stripe-rails` and `laravel`-style engines aside, most apps write the handler by hand. Return 200 quickly and enqueue the work (PERF-013), and store the provider's event id to make retries idempotent (SEC-051).

## webhook verification snippet
```ruby
# app/controllers/webhooks/stripe_controller.rb
class Webhooks::StripeController < ApplicationController
  skip_before_action :verify_authenticity_token
  skip_before_action :authenticate_user!, raise: false

  def create
    payload = request.raw_post
    sig = request.env["HTTP_STRIPE_SIGNATURE"]
    secret = Rails.application.credentials.dig(:stripe, :webhook_secret) || ENV.fetch("STRIPE_WEBHOOK_SECRET")
    begin
      event = Stripe::Webhook.construct_event(payload, sig, secret)
    rescue JSON::ParserError, Stripe::SignatureVerificationError
      return head :bad_request
    end
    ProcessStripeEventJob.perform_later(event.id, event.type)
    head :ok
  end
end
```
`Stripe::Webhook.construct_event` enforces the timestamp tolerance itself (default 300 seconds), which is the replay defence SEC-051 asks about. For other providers, see that provider's stack file; the raw-body rule is the same.

## data access
ActiveRecord. Models `app/models/`, schema `db/schema.rb` (or `db/structure.sql` when `config.active_record.schema_format = :sql`), migrations `db/migrate/`, connection config `config/database.yml` reading `DATABASE_URL` or per-key `host`/`username`/`password`. Seeds `db/seeds.rb` (DAT-016 — check whether anything runs it in production).

**Connection pooling** (DAT-008): `pool:` in `config/database.yml`, which must be at least Puma's `threads` count plus whatever the job worker uses in the same process, or requests block waiting for a connection. An external pooler (PgBouncer, RDS Proxy, Supabase's pooler port) sits in front and changes the answer — check the host and port in `DATABASE_URL`. **Row-level security** (DAT-001, DAT-002): Rails does not use it. The app connects as one database user with full access to every row and all authorization is application code, so unless someone wrote `enable row level security` into a migration by hand, record RLS as not in use and let SEC-011 and DAT-026 carry that ground instead.

**SQL sinks** (SEC-038): `find_by_sql("... #{x}")`, `where("name = '#{params[:q]}'")`, `ActiveRecord::Base.connection.execute("... #{x}")`, `select_all`, `sanitize_sql_array` used wrongly, `joins("... #{x}")`, `pluck(Arel.sql(params[:col]))`. Safe forms: `where(name: x)`, `where("name = ?", x)`, `where("name = :n", n: x)`. Dynamic identifiers cannot be bound — `order(params[:sort])` and `pluck(params[:col])` must map through a hardcoded allowlist (SEC-040); Rails raises on unrecognised `order` values in recent versions but `Arel.sql` re-opens the hole.

**Mass assignment** (SEC-041): strong parameters are the guard — `params.require(:user).permit(:name, :email)`. The failures are `params.permit!`, `params.require(:user).permit!`, `permit(*params[:user].keys)`, and any model write taking `params[:user]` directly. Rails 8 adds `params.expect(user: [:name, :email])` as the preferred form; check the version before flagging its absence. Second layer: read the schema for `admin`, `role`, `credits`, `plan`, `verified`, `stripe_customer_id` and confirm no permit list reaches them.

**N+1 and pagination**: `includes`/`preload`/`eager_load` (DAT-010); the `bullet` gem in the `Gemfile` means the project already detects these in development. Pagination is `kaminari`, `pagy`, or `will_paginate` — none is built in, so a bare `Model.all` in an index action is DAT-011.

**Serialization** (SEC-042): `render json: @user` calls `as_json` and returns every column including `encrypted_password` unless the model overrides `as_json`/`serializable_hash` or the action uses a serializer (`ActiveModel::Serializers`, `jbuilder` templates in `app/views/**/*.json.jbuilder`, `blueprinter`, `alba`).

**Migrations for DAT-015**: Rails reads `DATABASE_URL` from the environment by default, so a one-shot prefix redirects it: `DATABASE_URL=postgres://<user>@<host>/prelaunch_scratch bin/rails db:migrate`. Confirm the redirect took with `DATABASE_URL=... bin/rails db:version` before running anything that writes. Never run `db:reset`, `db:drop`, or `db:schema:load` against a database the app or the audit uses. Rollbacks are the `down`/`change` reversibility of each migration; `bin/rails db:rollback STEP=1` is the mechanism and an irreversible migration raises `ActiveRecord::IrreversibleMigration`.

## file uploads
**ActiveStorage** is the default: `has_one_attached :avatar` / `has_many_attached :files` on the model, the `active_storage_blobs`/`attachments`/`variant_records` tables in the schema, and services in `config/storage.yml`. Each service entry can carry `public: true`, which makes every object in that bucket world-readable and is DAT-005's finding; the default `amazon`/`google` service is private and URLs go through Rails as a signed, expiring redirect (`ActiveStorage::Blob.service_urls_expire_in`, five minutes by default) — that is the SEC-050 mechanism. `rails_blob_path`/`url_for(record.avatar)` produce those signed URLs; `record.avatar.url` on a public service produces a permanent one.

ActiveStorage validates nothing by itself: no extension allowlist, no content sniffing, no size cap (SEC-047, SEC-049). Look for the `active_storage_validations` gem, a custom `validate :acceptable_file`, or an `image_processing`/`vips` re-encode. Direct uploads (`file_field direct_upload: true`) POST straight to the service and bypass the controller entirely, so any check written only in the controller does not run.

Other libraries: CarrierWave (`app/uploaders/`), Shrine (`app/uploaders/`, plugins), Paperclip (unmaintained). Request body size is capped by the web server (Puma has no limit by default; nginx `client_max_body_size` and the platform's own limit are the real ceilings — SEC-067).

## background jobs
ActiveJob is the interface (`app/jobs/**/*_job.rb`, `MyJob.perform_later(args)`); the adapter is what matters. `config.active_job.queue_adapter` in `config/application.rb` or `config/environments/production.rb`:
- `:async` — the default when nothing is set. In-process thread pool, jobs are lost on restart or crash, and it is not a queue for anything that matters (PERF-013, REL-019).
- `:sidekiq` — Redis, `config/sidekiq.yml`, worker started with `bundle exec sidekiq`. Web UI `Sidekiq::Web` mounted in `routes.rb` (SEC-013 unless wrapped in an admin constraint). `sidekiq-cron` or the Enterprise scheduler for recurring work.
- `:good_job` — Postgres-backed, `bundle exec good_job start`, dashboard engine mountable, cron in `config.good_job.cron`.
- `:solid_queue` — Rails 8's default in new apps, `config/queue.yml`, `config/recurring.yml`, worker `bin/jobs`. Check the version.
- `:delayed_job`, `:resque`, `:sneakers` in older apps.

Confirm the worker process is actually started in production: read `Procfile`, `docker-compose.yml`, the systemd unit, or the platform config. A queue with no running worker is jobs that never run, and it looks identical to a working system from the request side (REL-019).

Mail: `deliver_later` enqueues, `deliver_now` sends inline in the request (PERF-013). Scheduled work outside a job runner: the `whenever` gem writes a crontab from `config/schedule.rb`; a bare `cron` entry calling `bin/rails runner` is also common.

## error handling and logging
`config/environments/production.rb` is the file:
- `config.consider_all_requests_local = false` — if true, every production error renders the full stack trace, source, and local variables to the browser (SEC-009, SEC-008).
- `config.action_dispatch.show_exceptions` — modern Rails takes `:all` / `:rescuable` / `:none` rather than `true`/`false`; check what the version expects before reading the value.
- `config.force_ssl = true` — redirects HTTP, marks cookies secure, and sets HSTS (SEC-032, SEC-034).
- `config.log_level`, `config.log_tags`, `config.logger`. `lograge` for structured single-line logs. `RAILS_LOG_TO_STDOUT`.
- `config/initializers/filter_parameter_logging.rb` sets `config.filter_parameters` — the generated list covers `passw`, `secret`, `token`, `_key`, `crypt`, `salt`, `certificate`, `otp`, `ssn`; anything the app logs outside that list is REL-015's problem, and a custom logger call that dumps `params.to_json` bypasses the filter entirely.

Error pages: static `public/404.html`, `public/422.html`, `public/500.html`, or a routed controller via `config.exceptions_app = self.routes`. `rescue_from` blocks in `ApplicationController` map exceptions to statuses — read them for handlers that render `e.message` into the response (SEC-009).

Reporting: `sentry-ruby` + `sentry-rails` in `config/initializers/sentry.rb` (`Sentry.init`), with `sentry-sidekiq`/`sentry-delayed_job` needed separately so the worker process reports too (REL-001). `Rails.error.report` is the framework's own error-reporter interface in 7.0+. Honeybadger, Bugsnag, Rollbar, Appsignal all install the same way. Check `config.filter_parameters` is passed through to the reporter's scrubber (REL-002).

## security headers
`config.action_dispatch.default_headers` in `config/application.rb` or an environment file. The framework defaults include `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `X-Permitted-Cross-Domain-Policies: none`, and `Referrer-Policy: strict-origin-when-cross-origin` — confirm the app has not replaced the hash wholesale, which silently drops the ones it does not re-list (SEC-033).

CSP: `config/initializers/content_security_policy.rb` is generated but entirely commented out in a new app, so its presence proves nothing — read whether the `config.content_security_policy do |policy|` block is live (SEC-031). `content_security_policy_nonce_generator` plus `nonce: true` on `javascript_tag`/`javascript_include_tag` is the nonce path. `config.content_security_policy_report_only = true` means the policy is not enforced.

HSTS: `config.force_ssl = true` with `config.ssl_options = { hsts: { expiry: 1.year, subdomains: true, preload: true } }` (SEC-032). The `secure_headers` gem replaces all of the above with its own initializer if present.

CORS: `rack-cors` in `config/initializers/cors.rb` — `origins '*'` with `credentials: true` is SEC-035. Rails sends no `X-Powered-By`, but Puma or the proxy in front may add `Server` (SEC-065).

## known traps
- `params.permit!`, `params.require(:x).permit!`, or a model write taking `params[:x]` whole: SEC-041.
- `html_safe` or `raw()` on user, database, or CMS content; `sanitize` called with no allowlist argument is permissive by default: SEC-043.
- `skip_before_action :authenticate_user!` without `only:`, or with an `except:` that misses a new action: SEC-010, SEC-012.
- `skip_before_action :verify_authenticity_token` outside a signature-verified webhook, or `config.api_only = true` on an app that still authenticates by session cookie — API mode removes the CSRF middleware entirely and nothing replaces it: SEC-030.
- `find_by_sql`, or a string-interpolated `where`/`joins`/`execute`: SEC-038. `order(params[:sort])` or `Arel.sql(params[:col])`: SEC-040.
- `config/master.key` or `config/credentials/*.key` tracked by git: SEC-001, and SEC-002 if it was ever committed.
- `config/storage.yml` with a `public: true` service, or an S3 bucket whose objects were made public outside Rails: DAT-005, DAT-006.
- `mount Sidekiq::Web => '/sidekiq'`, `GoodJob::Engine`, `PgHero`, or `Flipper::UI` in `routes.rb` without an admin constraint or HTTP basic auth: SEC-013.
- `config.consider_all_requests_local = true` in `config/environments/production.rb`: SEC-009, SEC-008.
- `config.force_ssl` unset or false in production: SEC-034, SEC-032, and SEC-025 because the session cookie is then not marked `Secure`.
- `render json: @model` with no serializer: every column, including anything encrypted-at-rest or internal, goes over the wire (SEC-042).
- `redirect_to params[:return_to]` or `redirect_to params[:next]` without an allowlist: SEC-029. Rails raises on cross-host redirects by default under `config.action_controller.raise_on_open_redirects`; confirm the app's `load_defaults` version enables it rather than assuming.
- `send_file` or `send_data` built from a request-supplied path: SEC-046.
- The `:async` ActiveJob adapter left in production, or a queue adapter configured with no worker process started: PERF-013, REL-019.
- `db/seeds.rb` wired into the deploy, or a seeded admin with a known password: DAT-016, SEC-060.
- A JS bundler build script carrying `--sourcemap` into `public/assets/`: SEC-007.
- Devise `config.paranoid = false` (the default), which makes reset and confirmation responses distinguish existing from unknown addresses: SEC-018.
- Browser drivers, when a check needs one: only use `playwright`, `puppeteer`, `@playwright/test`, `cypress`, or `selenium` if the project already depends on one (`package.json` devDependencies, or a `capybara` + `selenium-webdriver` pair in the `Gemfile`'s test group); never install one for the audit. Cited by the accessibility and compliance domain headers, COMP-007, and FLOW-018.

## runtime probe hints
**Session cookie for `curl`.** A server-rendered Rails login is a form POST protected by CSRF, so a bare POST returns 422. Fetch the form, lift the `authenticity_token`, then post it back with the same jar:
```bash
JAR=.pre-launch/flows/cookies.txt
TOKEN=$(curl -s -c "$JAR" http://localhost:3100/users/sign_in \
  | grep -o 'name="authenticity_token" value="[^"]*"' | head -1 | sed 's/.*value="//;s/"$//')
curl -s -b "$JAR" -c "$JAR" -X POST http://localhost:3100/users/sign_in \
  --data-urlencode "authenticity_token=$TOKEN" \
  --data-urlencode "user[email]=qa+$(date +%s)@example.com" \
  --data-urlencode 'user[password]=<from credentials_env>' -i
curl -s -b "$JAR" http://localhost:3100/dashboard -o /dev/null -w '%{http_code}\n'
```
Devise's default paths are `/users/sign_in`, `/users/sign_up`, `/users/sign_out` (DELETE, and it also needs the token); a hand-rolled or Rails 8 generated auth uses `/session` and `/registration` or whatever `bin/rails routes -g session` prints. Get the real paths and the real parameter names from `bin/rails routes` before writing the curl — the `user[email]` nesting is Devise's, not universal. If the app is `api_only`, there is no form and no token: POST JSON to the sign-in route and read the response body or the `Authorization` header.

**Cookie names.** The session cookie is `_<app_name>_session` unless `config/initializers/session_store.rb` says otherwise — read that file, it is one line. Devise remember-me is `remember_user_token`. Nothing else in a default Rails app is load-bearing for a probe.

**JWT for API probes.** Only if the app issues one. `devise-jwt` returns it in the `Authorization` response header on a successful sign-in (`curl -i` and read `Authorization: Bearer ...`); `doorkeeper` exposes `POST /oauth/token` with `grant_type=password` or a client-credentials pair; a hand-rolled API usually has a `POST /api/v1/login` returning `{"token": "..."}`. Otherwise the session cookie is the only credential and there is no bearer surface: record `n/a — no token endpoint` for the bearer half. DAT-002's per-user RLS probe wants a data API that authorizes by the user's own token, which Rails does not provide — the database credential is the app's single connection user, so record `n/a — no PostgREST surface` there and rely on the cookie probes plus DAT-026 for the DB user's privileges.

**Health path.** `GET /up` is generated into `config/routes.rb` in Rails 7.1 and later (`get "up" => "rails/health#show"`), returns 200 with an empty green page, and checks nothing but that the app booted — which is REL-006's finding, not a pass. Older apps have no convention: grep `bin/rails routes -g 'health|status|ping'`. If nothing exists use the cheapest static page for cold-start timing and say which you used.

**Not-found behaviour.** An unmatched path raises `ActionController::RoutingError` and renders `public/404.html` with status 404 in production; in development it renders the routing-error page listing every route, which is itself SEC-008 if it ever reaches production. `ActiveRecord::RecordNotFound` from `find`/`find_by!` maps to 404 in production and to a stack trace in development. Check the status code and not just the body: a catch-all route rendering a "not found" view with status 200 is a soft 404 (SEO).

**Test-mode provider keys.** Read the running process first (`printenv | grep -iE 'stripe|paypal|paddle'`), then `.env` and `.env.local`, then credentials via `bin/rails runner 'puts Rails.application.credentials.dig(:stripe, :secret_key).to_s[0, 8]'`. Stripe `sk_test_` / `pk_test_` / `rk_test_` and a `whsec_` from `stripe listen` rather than the dashboard; PayPal pointing at `api-m.sandbox.paypal.com`; Paddle, Lemon Squeezy, and RevenueCat a sandbox host, flag, or key. Published test card numbers live in the payment provider's own stack file. If the classification is ambiguous, treat the keys as live and stop.

**Local mail catcher.** In order of likelihood: `letter_opener` (`config.action_mailer.delivery_method = :letter_opener` in `config/environments/development.rb`) writes each message as HTML under `tmp/letter_opener/` and opens a browser — read the newest directory there rather than expecting an HTTP API; `letter_opener_web` mounts a UI at whatever path `routes.rb` gives it. `config.action_mailer.delivery_method = :file` writes plain-text messages to `tmp/mails/`, which is the easiest thing to grep. `:test` collects into `ActionMailer::Base.deliveries` in-process and is unreadable from outside. Otherwise check `docker-compose.yml` for `axllent/mailpit` (SMTP `1025`, HTTP `8025`, `curl -s http://localhost:8025/api/v1/messages`), `mailhog/mailhog` (API `/api/v2/messages` on `8025`), or the `mailcatcher` gem (SMTP `1025`, HTTP `1080`, `curl -s http://localhost:1080/messages`). `/rails/mailers` renders previews with fixture data and is what HYG-016 wants, but it is not a capture of a real send. No reachable catcher is `error: no mail capture`, never a pass.

**Throwaway identity.** Sign up through the app's own registration route with `qa+<unix-ts>@example.com` and the password from the config's `credentials_env`, using the token dance above; never reuse the shared test account where a check needs a second identity. Clean up afterwards with `bin/rails runner 'User.where("email like ?", "qa+%@example.com").destroy_all'` — `destroy_all` rather than `delete_all` so dependent records and attachments go too, which is also how you verify DAT-020's cascade.
